调整曲线实验室：用公开公式算三条可复算的调色曲线

调色工具最容易被写成「拖一下滑杆，图变好看了」，但滑杆背后到底是什么，很少有人写清楚。这篇反过来：先把公式摆出来，再用一张色阶图跑三档参数，把每个关键灰阶的输入值和输出值列成表，读者拿计算器就能核对。

三条曲线

同一张色阶图在亮度、对比度、饱和度三档参数下的输入输出。横轴输入，纵轴输出，直线代表「什么都没改」。

为什么要把公式写出来

因为「变亮」和「提对比」在视觉上很像，数学上完全是两回事。写出来之后，很多争论就不用吵了：某个效果做不到，是公式本身没有那一项，不是你没找对参数。本站 色彩调整 用的就是下面这三条，页面不藏参数。

标本：一张色阶图

picstudio-tone-chart.png 是一条从 0 到 255 的灰阶，加几块固定色块。选它不是因为好看，是因为输入输出一一对应，任何一个像素偏了都能立刻看出来。另备 JPEG 版 用来观察有损编码叠加调色之后的误差。

曲线一：亮度平移

最朴素的一条：out = clamp(in + b)。参数 b 取 −40 / 0 / +40 三档。0、128、255 三个点的输出分别是 0→40、128→168、255→255。注意两端：低光被抬起来了，高光到 255 就被截断，细节不会再多出来。

所以「亮度 +40 让暗部有层次」是错的——它只是把暗部整体搬上去，被截断的地方反而丢层次。表里这一栏最容易被误读。

曲线二：对比度绕中点

out = clamp((in − 128) × c + 128)，c 取 0.8 / 1.0 / 1.3。中点 128 不动，两端被向外推或向内收。c=1.3 时 0 仍为 0、255 仍为 255，但 64 变成约 45、192 变成约 211。

这与亮度平移的根本区别就在这：对比度不动中点，只拉两端距离。想让整张图变亮，调对比度永远达不到；想让灰蒙蒙的图拉开层次，调亮度也只会把整体搬亮。两张表并排看最直观。

曲线三：饱和度插值

先算灰度 l = 0.2126R + 0.7152G + 0.0722B，再按 out = clamp(l + (in − l) × s) 插值。s=0 变灰，s=1 原样，s=1.5 更艳。这条曲线对纯灰阶不起作用——因为灰阶上 in = l，插值项恒为 0。

这解释了一个常见困惑：「饱和度拉满，为什么黑白照片一点没变」。不是工具坏了，是公式对无彩度像素本来就没有可放大的量。

三档参数对照表

把三个输入点 32 / 128 / 224 在九种组合下的输出列成表，能读出几件确定的事：亮度平移在高端必然截断；对比度在中点恒等；饱和度对灰阶恒等；三条叠加时顺序会影响结果，因为截断发生在每一步之后。报告里给的是逐点数值，不是「看起来更通透」这类形容词。

一次调整做不到的三件事

  1. 把已经截断成 255 的高光恢复出细节——信息没了。
  2. 靠对比度让整体变亮——中点不动。
  3. 靠饱和度让黑白图有色——插值项为零。

把这三条写进工具页的说明里，比事后解释「为什么没效果」省事得多。

本站工具与公式的对应

色彩调整 对应上述三条；滤镜 是固定参数组合，不额外引入新公式；图片对比 用来并排看处理前后，避免靠记忆判断「好像亮了」；格式转换 只改容器，不改像素值。全部本地计算，所以表里的数字可以用浏览器控制台读回验证。

自己复算

下载色阶图，用任一能读像素的工具取 32/128/224 三点，代入上面三条公式，跟报告表格逐个对。若对不上，先查是不是在 8 位量化前多除了一次 255，或者先做了 gamma 变换——这两个是最常见的偏差来源，我们这份表用的是直接 8 位整数运算，没有额外色彩空间转换。

常见问题

亮度加到底为什么高光没细节？

clamp 到 255 就截断了，平移不会凭空造层次。

对比度能让灰图变亮吗？

不能，公式绕 128 中点，中点恒等。

饱和度拉满黑白图没反应？

正常，灰阶上插值项恒为 0。

三条一起调，顺序有影响吗？

有，每步截断会改变下一步输入。
