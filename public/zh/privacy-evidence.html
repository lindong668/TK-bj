隐私实证，而不是一句承诺

PicCalc 在浏览器标签页里处理图片。这一页给你一套一分钟左右就能复现的测试，也把“本地处理”的边界讲清楚，免得把不该放心的事情也放心了。

这里的“本地”指什么

选择文件后，浏览器用 File API 读取，并解码成页面内的 ImageBitmap 或 canvas。缩放、调色、裁剪、格式转换、清除 EXIF，都是对这些像素做运算。保存时调用 canvas.toBlob()，交给你一个临时的 blob: 地址。工具代码里没有上传接口。

60 秒复现

  1. 打开任意工具，例如图片压缩。
  2. 按 F12 打开开发者工具，切到 Network（网络），清空列表。
  3. 上传一张较大的照片并调整参数，观察预览更新时列表的变化。
  4. 用 Fetch/XHR 过滤。你会看到页面资源请求，但没有任何请求的正文是你的照片。
  5. 更严格的做法：页面加载完后，把 Network 切到 Offline（离线） 再处理一次。工具照常工作，因为它不需要网络。

想直接看代码也可以：工具脚本是公开文件，例如 /assets/js/lab.js 和各工具自己的脚本。搜索 fetch(、XMLHttpRequest、sendBeacon，没有任何一处把图片数据交给它们。

不保存什么

没有账号、没有云端相册、没有服务器副本。解码后的图片只活在当前标签页的内存里，关闭或刷新即消失。下载文件由本地 blob 生成。

需要知道的边界

  • 托管访问日志仍然存在。 打开页面本身会经过 CDN，日志里有网址、时间和 IP，但没有你的图片。
  • 浏览器与扩展不在我们控制范围内。 截图扩展、同步剪贴板都可能复制你屏幕上的内容。
  • 去元数据是单独一步。 压缩不一定会删掉 EXIF；在意拍摄地点时请用EXIF 查看与清除。
  • 超大文件会撞上浏览器内存上限。 编辑类工具的工作边长上限为 3000 px，裁剪与放大上限为 4000 px。
