QR Code Error Correction and Capacity: L, M, Q, H Explained

A QR code can be dirty, torn, half-covered by a logo and still scan perfectly. That is not luck — it is error correction, and it is the single setting that decides whether your code survives the real world. Here is what the four levels mean and how to choose one.

What error correction actually does

A QR code stores your data plus a set of redundancy blocks computed from it. When a scanner cannot read a part of the image, it uses the redundant data to reconstruct what is missing. The more redundancy you ask for, the more damage the code can survive — and the more space that redundancy takes up.

Four levels are defined in the standard:

LevelCan be restoredTypical use
L (Low)about 7% of the codewordsClean digital display, short URLs
M (Medium)about 15%Default in most generators — a sensible balance
Q (Quartile)about 25%Printed posters, packaging, minor wear expected
H (High)about 30%Codes with a logo or image in the centre, industrial labels

Note that the percentage is of codewords, not of the picture area — but as a rough guide, level H tolerates roughly a third of the code being obscured.

The trade-off nobody mentions

Higher correction is not free. More redundancy means more modules (the little squares) for the same message, which means:

  • the code looks denser and each module becomes smaller;
  • it needs to be printed or displayed larger to stay scannable;
  • a low-resolution screen or a cheap printer may simply fail to resolve the individual modules.

Practical rule: pick the lowest level that still covers your risk. A code on a screen rarely needs more than M. A code printed on a flyer that will be folded, or one carrying a logo, should use Q or H.

Versions and how much actually fits

"Version" is simply the size of the grid. Version 1 is 21×21 modules; every step adds four modules per side, up to Version 40 at 177×177. Bigger version means more capacity.

Content typeMost efficientWhy
Digits onlyup to 7,089 characters (Version 40, level L)Three digits are packed into ten bits
Uppercase letters, digits, a few symbolsup to 4,296Alphanumeric mode, two characters per 11 bits
Any text (UTF-8)up to 2,953 bytesByte mode, one byte per eight bits
Chinese, Japanese, Arabicfewer characters than Latin textEach character costs 2–3 bytes in UTF-8

This is why a long URL pushes the version up quickly: every extra character adds modules, and every redundancy block from a higher error correction level adds more. Shorten the URL first if your code is getting dense.

Why a logo in the middle still scans

Putting a logo in the centre works precisely because of error correction — the covered modules are treated as damage and reconstructed. It is not a special feature, it is the redundancy doing its job. That also means:

  • it only works reliably at level H (or Q at a push);
  • the logo should stay well inside the area — roughly 20–25% of the width is the practical ceiling;
  • you must test the finished code with a real phone before printing a thousand copies.

Design rules that keep a code scannable

  • Keep the quiet zone. A margin of at least four modules on all four sides, in a light colour. Scanners use it to find the code's edges; without it, detection often fails outright.
  • Do not invert the colours. Many scanners expect dark modules on a light background. A white-on-black code may fail on older readers.
  • Keep contrast high. Dark navy on white is fine; light grey on white is not. Avoid gradients that cross the modules.
  • Never distort it. Stretching a QR code non-uniformly breaks the module grid. Resize proportionally only.
  • Mind the surface. Glossy reflections, fabric texture and curved surfaces all reduce effective contrast — raise the error correction level to compensate.

How big does a printed code need to be?

The practical limit is the scanning distance, not the printing press. A widely used rule of thumb is a ratio of about 10:1 — the scan distance should be roughly ten times the code's width:

Scan distanceMinimum code width
Hand-held, ~10 cmabout 2 cm
Arm's length, ~30 cmabout 3 cm
Poster, ~1 mabout 10 cm
Shop window, ~3 mabout 30 cm

Also give each module enough physical size: at 300 DPI printing, a module should be at least 3–4 pixels wide, which for a medium-density code means roughly 1 cm or more overall.

Frequently asked questions

Which error correction level should I use?
M is a safe default for digital display. Move to Q for anything printed that may get scuffed, and to H if you are placing a logo or image over part of the code.
Why did my QR code turn into a dense mess of tiny squares?
Because the data plus the redundancy needed more modules than the current version holds, so the generator moved to a higher version. Shorten the URL or lower the error correction level.
Can I put my logo in the middle?
Yes, if you use level H and keep the logo to roughly 20–25% of the code width. Always test the finished design with a real phone before printing.
Why does my QR code not scan on some phones?
Most often it is low contrast, a missing quiet zone, an inverted colour scheme, or the code being too small for the distance it is scanned from. Check those four first.
Does a QR code ever expire?
No — a static QR code is just an encoded string and works forever. Only codes generated by a service that redirects through its own short link can stop working if that service shuts down.

二维码容错级别与容量：L、M、Q、H 到底什么意思

二维码脏了、破了、中间盖了个 logo，照样能扫出来——这不是运气，而是容错机制在起作用。它也是决定你的码在真实环境里能不能活下来的唯一关键设置。这篇讲清四个级别怎么选。

容错到底做了什么

二维码里除了你的数据，还有一批由数据算出来的冗余块。当扫描器读不到某一部分时，就用这些冗余信息把缺的部分推回来。你要的冗余越多，能扛的损坏越大——但冗余本身也要占地方。

标准里定义了四个级别：

级别可恢复比例典型用途
L（低）约 7% 的码字干净的数字屏幕显示、短链接
M（中）约 15%多数生成器的默认值，平衡得当
Q（较高）约 25%印刷海报、包装，预期会有磨损
H（高）约 30%中间放 logo、工业标签

注意这个比例是按码字算的，不是按画面面积——但粗略理解成「H 级能扛掉约三分之一的码」是够用的。

没人告诉你的代价

更高的容错不是白给的。冗余变多意味着同样的内容需要更多模块（那些小方块），结果是：

  • 码看起来更密，单个模块更小；
  • 必须印得或显示得更大才扫得动；
  • 分辨率低的屏幕或廉价打印机可能根本还原不出单个模块。

实用原则：选能覆盖你风险的最低级别。屏幕上的码很少需要超过 M。会折叠的传单、或者中间带 logo 的码，应该用 Q 或 H。

版本与容量

「版本」就是网格的大小。版本 1 是 21×21 个模块，每升一级每边多 4 个，一直到最后版本 40 的 177×177。版本越大，装得越多。

内容类型最高容量原因
纯数字最多 7,089 个字符（版本 40、L 级）三个数字压缩进 10 个比特
大写字母 + 数字 + 少量符号最多 4,296字母数字模式，两个字符 11 比特
任意文本（UTF-8）最多 2,953 字节字节模式，一字节 8 比特
中文、日文、阿拉伯文比拉丁文字符数少UTF-8 下一个字符占 2–3 字节

这就是为什么长网址会让码迅速变密：每多一个字符就多些模块，而高容错级别还额外加冗余。先把网址缩短，是控制密度最有效的办法。

为什么中间放 logo 还能扫

中间放 logo 之所以可行，靠的正是容错——被盖住的模块被当成「损坏」，由冗余信息推回来。这不是什么特殊功能，就是冗余在干活。因此：

  • 只有在 H 级（Q 级勉强）下才可靠；
  • logo 要待在中间安全区内，宽度上限大约是整体的 20–25%；
  • 印一千份之前，务必用真手机测一遍成品。

让码始终可扫的设计规则

  • 留出静默区。四边至少留 4 个模块宽的浅色边距。扫描器靠它定位边界，没有它往往直接识别失败。
  • 不要反色。多数扫描器默认「深色模块 + 浅色底」。白码黑底在老一点的读码器上会失败。
  • 保持高对比。深蓝配白底没问题，浅灰配白底不行。避免渐变横跨模块。
  • 绝不变形拉伸。非等比拉伸会破坏模块网格，只能等比缩放。
  • 考虑承载面。反光、布料纹理、弧面都会降低有效对比度，用提高容错级别来补偿。

印刷尺寸要多大？

真正的限制来自扫描距离，不是印刷精度。常用经验法则是约 10:1——扫描距离约为码宽的十倍：

扫描距离码的最小宽度
手持，约 10 cm约 2 cm
一臂距离，约 30 cm约 3 cm
海报，约 1 m约 10 cm
橱窗，约 3 m约 30 cm

还要保证每个模块有足够物理尺寸：300 DPI 印刷时，单个模块至少应有 3–4 像素宽，对中等密度的码来说，整体大约要 1 cm 以上。

常见问题

该选哪个容错级别？
数字显示用 M 是稳妥默认。会磨损的印刷品升到 Q；如果码上要盖 logo 或图案，用 H。
为什么我的二维码变成一堆密密麻麻的小方块？
因为数据加冗余需要的模块超出了当前版本的容量，生成器自动升到更高版本。缩短网址，或降低容错级别。
中间能放 logo 吗？
可以，前提是用 H 级，且 logo 宽度控制在整体的 20–25% 以内。印之前一定用真手机测一遍成品。
为什么我的码在某些手机上扫不出来？
最常见的原因是对比度不足、没有静默区、用了反色，或者码相对扫描距离太小。先查这四项。
二维码会过期吗？
静态二维码只是一串编码的字符串，永远不会过期。只有那些通过服务商短链接跳转的「动态码」，才会因为服务商停摆而失效。
