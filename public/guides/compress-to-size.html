Compress an Image to an Exact File Size: Beating Upload Limits

An application form demands a photo under 200 KB; an attachment is capped at 500 KB. This guide explains why lowering quality so often fails, why capping the width works better, and gives you a repeatable procedure for working backwards from a target size.

First: the limit is file size, not dimensions

People often assume they must "make the image smaller", but what systems actually limit is file size in bytes (KB), not pixel dimensions. The two are related but not the same:

  • Pixel dimensions — a resolution such as 1920×1080.
  • File size — how many KB it takes to store those pixels.

At the same 1920×1080, a flat-colour icon might be 50 KB while a detailed landscape is 800 KB. The busier the image, the larger the file at the same dimensions.

Why lowering quality often fails

The JPG quality parameter controls how coarse the quantisation table is, but it only works if the original still contains redundancy to discard.

If your image has already been compressed once — sent through WeChat, downloaded as a web thumbnail, compressed by someone else — there is almost nothing left to remove. Worse, re-encoding sometimes makes the file slightly larger.

Quick test: drop quality from 90 to 60. If the size barely moves, the image is already wrung out and you need a different approach.

What actually works: capping the width

This is the most effective and most overlooked trick. The logic is simple: fewer pixels means less information to store.

  • 4000 px wide → 1600 px leaves about 16% of the pixels, and the file usually shrinks dramatically.
  • 4000 px wide → 800 px leaves about 4%.

The key insight: most systems do not need high resolution. An application photo might require 295×413 while your phone produces 4000×3000 — a dozen times more pixels than necessary.

Working backwards from a target size: three steps

  1. Fix the dimensions first. Find out what pixel size the target system asks for, then scale to just meet it, slightly over at most.
  2. Then fine-tune quality. Start at 80. If still too big, drop 10 at a time; if still over, go back to step 1 and reduce dimensions one more notch.
  3. Finally, zoom in and check. Look at text edges, face outlines and flat gradients for blocking or banding.

The order matters — dimensions before quality is far quicker and preserves better quality than the reverse.

Pitfalls to avoid

  • Re-saving the same JPG repeatedly. Each save discards more. Always export once from the original.
  • Crushing quality to hit a target. Below 50, blocking becomes obvious, especially around text and faces. Reduce dimensions instead.
  • Forgetting transparency. JPG output drops the alpha channel and fills it white or black. Use PNG and shrink dimensions instead.
  • Ignoring the format. WebP is typically 25%–35% smaller than JPG for the same content — if the target accepts it, that is the easiest win.

FAQ about compressing to a target size

Why did the file get bigger after compressing?
When the original is already heavily compressed, re-encoding removes nothing and metadata or encoding overhead can add a little. Cap the width instead of pushing quality lower.
What quality should I use?
70–80 for web images. When hitting a strict KB target, start at 75 and step down. Below 50 the damage is obvious — reduce dimensions instead.
Is there a one-shot setting?
No universal value exists, because image complexity varies. Reliably: lock the dimensions your target requires, then fine-tune quality. Two or three passes will land it.
Does compression keep transparency?
JPG output has no alpha channel, so transparent areas are filled white or black. Use PNG and reduce size with the Resize tool instead.
Can lost quality be recovered?
No. What lossy compression discards is gone. Keep the original and re-export from it every time.

图片压缩到指定 KB：报名、上传限制怎么破

「照片不能超过 200KB」——这种限制几乎人人遇到过。难点不在于会不会压缩，而在于怎么稳定地压到目标大小以内，同时画质还能看。这篇文章讲清背后的原理和一套可复用的操作步骤。

先搞清楚：限制的是文件体积，不是尺寸

很多人的第一反应是把图片「缩小」，但系统限制的是文件字节数（KB），不是像素尺寸。这两者相关但不等于：

  • Pixel size：1920×1080 这样的分辨率。
  • 文件体积：存储这些像素用了多少 KB。

同样是 1920×1080，一张纯色背景的图标可能只有 50KB，一张细节丰富的风景照可能有 800KB。画面越复杂，同样尺寸下体积越大。

为什么「调质量」常常压不动

JPG 质量参数控制的是量化表的粗细，但它有个前提：原图里得有可丢弃的冗余信息。

如果你拿到的图已经被压过一次（比如微信传过的、网站下载缩略图、别人工压缩过的），再压一次几乎压不掉东西——可丢的信息早就丢了。更糟的是，重新编码有时还会让文件略微变大。

判断方法：把质量从 90 调到 60，如果体积几乎没变，就说明这张图已经是「压干」的状态，必须换思路。

真正有效的手段：限制最大宽度

这是压体积最有效、也最容易被忽略的一招。原理很直接：像素总数减少了，需要存储的信息就少了。

  • 4000 px 宽 → 缩到 1600 px，像素总数降到约 16%，体积通常也大幅下降。
  • 4000 px 宽 → 缩到 800 px，像素总数降到约 4%。

关键在于：大多数系统并不需要高分辨率。报名照片通常只要求 295×413 或类似尺寸，而你手机拍出来是 4000×3000——这里白白浪费了十几倍的体积。

按目标大小反推：三步走

  1. 先定尺寸。查清目标系统要求的像素尺寸（报名表、招聘网站通常会写），把图片缩到刚好满足要求、略大一点即可，别超太多。
  2. 再用质量微调。尺寸定好后，质量从 80 开始试。如果超了，每次降 10 再试；如果还超，回到第 1 步把尺寸再降一档。
  3. 最后放大检查。重点看文字边缘、人脸轮廓、纯色渐变区域有没有出现块状或色带。

这个顺序很重要——先缩尺寸再调质量，比反过来省事得多，画质也更好。

几个容易踩的坑

  • 反复保存同一张 JPG。每保存一次就丢一次信息，来回几次画质明显下降。正确做法：始终从原图重新导出一次到位。
  • 为了压到目标大小把质量调到很低。质量低于 50 后，块状伪影会非常明显，尤其在文字和人脸边缘。宁愿再缩一点尺寸。
  • 忽略了透明背景。压缩输出为 JPG 时会丢掉透明，透明区域被填成白或黑。需要保留透明请用 PNG 并靠缩小尺寸来减体积。
  • 没注意格式。同样内容转成 WebP 通常比 JPG 再小 25%–35%，如果目标系统接受 WebP，这是最省事的一招。

关于压缩到指定大小的常见问题

Why did the file get bigger after compressing?
原图已经是高度压缩状态时，重新编码不但压不掉东西，还可能因为元数据或编码开销略微变大。此时应改用「限制最大宽度」而不是继续调低质量。
What quality should I use?
网页配图 70–80；要求严格控制体积时先试 75，不够再逐步下调。低于 50 画质损失就很明显了，这时更该做的是缩小尺寸。
有没有一步到位的办法？
没有万能参数——每张图的复杂度不同。可靠做法是先锁定尺寸（按目标系统要求），再用质量做微调，两三次就能稳定压到目标以内。
Does compression keep transparency?
输出 JPG 不支持透明，透明区域会被填充成白色或黑色。需要保留透明请改用 PNG，并通过「尺寸调整」减小体积。
Can lost quality be recovered?
不能。有损压缩丢弃的信息无法找回，请务必保留原图，每次都从原图重新导出。
