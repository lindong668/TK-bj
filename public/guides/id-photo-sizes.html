📐 Image Size & Pixel Standards

A "size" is only meaningful when you say both the pixel dimensions and the density they are displayed or printed at. This guide collects the numbers that actually come up when you build a favicon, prepare a social card or send a file to print.

Favicon and icon sizes

A modern favicon.ico should carry 16, 32, 48, 64, 128 and 256 px entries in one container. Browsers pick the closest one for a tab, a bookmark or a desktop shortcut; the 256 px entry is used for high-DPI displays and PWA install prompts. Separate PNGs at 180×180 (apple-touch-icon) and 192/512 px (web app manifest) cover the mobile cases.

What 16 × 16 can actually show — and where to start

A 16 × 16 icon has 256 pixels in total. It is the classic favicon size inherited from IE and it still shows up in browser tabs, bookmarks, history lists, Windows "small icons / details" views, old window title bars, system trays and many browser-extension toolbars. It is a compatibility marker, not a canvas for detail. Google site icons need at least 48 × 48, PWA / desktop shortcuts use 192 and 512, and iOS apple-touch-icon is 180 × 180 — none of those can be served by a 16 px entry.

Good source material for 16 / 32 px: a single letter, a flat geometric mark, a two-colour high-contrast logo. Bad source material: QR codes, faces, screenshots with small text, thin strokes, gradients, soft shadows and busy photos. Downscaling can only discard pixels; it cannot invent detail, and this site deliberately does not use an AI upscaler.

Practical starting points: keep 16 px in the .ico for legacy coverage; start at 32 px if you want any visible shape; use 64 px or larger for QR codes, portraits, or screenshots containing text; ship 180 / 192 / 512 separately for mobile and PWA. When cropping a tall screenshot or a wide photo, frame the subject so it fills the square, then design the 16 and 32 px versions by hand with a bolder outline and 10–15% padding.

Why the same name maps to different pixels

Print labels such as "1 inch" describe physical millimetres, not pixels. At 300 DPI a 25×35 mm print is about 295×413 px; at 150 DPI it is about 148×207 px. Whenever a platform gives millimetres, multiply by DPI and divide by 25.4 to get pixels — and always follow the receiving platform's own specification over a generic chart.

Web and social canvases

Common canvases are 1200×630 for link previews, 1080×1080 for square posts, 1080×1350 for portrait posts and 1920×1080 for a hero. These are pixel dimensions with no DPI attached: what matters is the aspect ratio and the file size budget, not a print density.

DPI, PPI and what they do not change

Changing the DPI tag in a file's metadata does not add detail. Enlarging a small image resamples existing pixels and invents the missing ones, so edges get soft. If you need a larger print, start from a larger capture rather than upscaling a thumbnail.

Frequently asked questions

What sizes should a favicon.ico contain?
16, 32, 48, 64, 128 and 256 px in one file covers browser tabs, bookmarks, Windows shortcuts and high-DPI displays. The ICO Generator on this site builds all six from one image.
Why is my 16 × 16 favicon blurry?
Because it has only 256 pixels. A QR code, a face or a line of small text cannot fit — this is a physical limit, not a bug in the tool. Keep the 16 px entry for compatibility, start at 32 px for visible detail, and use 64 px or larger for QR codes and portraits. Redraw the 16 / 32 px versions as a bold, simple, high-contrast mark.
Is 72 DPI still required for web images?
No. Screens use pixels. The DPI metadata is ignored by browsers; only the pixel dimensions and the byte size matter.
Why does my print look blurry at 300 DPI?
Because the source did not have enough pixels to begin with. DPI is a scaling instruction, not extra detail.
Are size charts universal?
No. Icon, social and print specs differ by platform and by receiving organisation. Treat charts as a starting point and verify against the official requirement.
