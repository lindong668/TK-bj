How to split a long image

  1. Upload a long image (chat screenshots, full-page captures, etc.)
  2. Choose a method: split into equal parts, or set a fixed height per slice
  3. Click "Split" and all slices are listed below
  4. Download a single slice, or use "Download all" to save them at once

How it works

When splitting by count, the total height is divided by the number of parts, and the last slice absorbs any remainder — so individual heights can differ by 1–2 px.

When splitting by fixed height, slices are cut from the top down, and any leftover shorter than one slice becomes its own slice — no content is lost.

Splitting simply copies pixels from vertical ranges of the original canvas, with no scaling or resampling, so every slice keeps the original sharpness.

FAQ about splitting

Does splitting reduce quality?

No. Splitting is pure pixel copying with no scaling or recompression, so each slice matches the corresponding region exactly.

Can I split horizontally?

This version supports vertical (height-based) splitting only, which covers most long-image needs. For horizontal, use the Crop tool first.

Will downloading all at once miss files?

Browsers throttle consecutive downloads, so the tool waits 350 ms between slices. If your browser asks whether to allow multiple downloads, choose Allow.

How many slices can I make?

Up to 20 by count. Splitting by height depends on the total height, so there is no real upper limit.

Two ways to cut, and how the remainder is handled

By count, the height is divided by the number of parts with ceil, then that quotient is used for every slice, so the last one is usually shorter. A 5000 px capture split into three gives slices of 1667, 1667 and 1666 — not three exact thirds, because pixels are whole. By fixed height, the requested height is honoured where possible and the final slice takes whatever is left, even if it is only a few pixels tall. No content is ever dropped and no slice is ever padded.

The practical difference matters for chat exports. Splitting by count is what you want when the receiving platform limits attachments — five slices means five files, evenly sized. Splitting by height is what you want when each slice must fit under a height limit, such as a story format or a preview pane. Choose the height method, set the limit, and check the last file before sending the set.

Splitting is a copy, not a re-encode

Every slice is cut from vertical ranges of the original canvas. There is no scaling and no smoothing, so text remains as sharp in slice four as in slice one, and thin rules are not resampled into grey. The trade-off is that the total pixel count is preserved: five 1080 × 1000 slices weigh about as much as the original 1080 × 5000 file, and PNG keeps them larger than the source JPEG. If the set must travel by email, compress the slices or convert them afterwards.

Because the cut is axis-aligned, a horizontal line of text that straddles a boundary is cut in half. There is no overlap and no "smart" boundary detection. When a cut lands badly, change the slice count by one and the boundaries move.

Why downloads arrive one at a time

Browsers throttle rapid consecutive downloads, so the page waits about 350 ms between files. If a browser asks whether the site may download multiple files, allowing it is what makes the batch complete; blocking it usually leaves only the first slice saved. Nothing is uploaded during this process — the waiting happens locally, and closing the tab cancels the remaining saves.

Limits worth knowing before you start

  • Vertical cuts only. A wide banner is not split into columns; use Crop Image for that.
  • 2–20 slices by count, 100–8000 px by height. Outside those ranges the control will not accept the value, which is deliberate: a one-pixel slice is not a useful file.
  • The browser canvas ceiling applies. An extremely long capture may fail to load at all — typically beyond roughly 32,000 px. Split it in a desktop editor, or capture it in two passes.
  • No preview of individual slices before splitting. The slice list appears after the operation, and each can be downloaded separately, so a bad boundary costs one more run rather than a lost original.
  • Output is PNG for every slice, with the original alpha preserved. There is no JPEG option and no per-slice quality control.

Two more questions this page gets

Why are my slices not exactly the same height?
Because the total height rarely divides evenly by the slice count. The quotient is rounded up and the last slice absorbs the difference, so a two-pixel variation is normal and not a processing error.
Can I split a tall image into a fixed number of files that each fit a byte limit?
Not directly — the controls work in pixels, not kilobytes. Split by height first, then compress or convert each slice to meet the byte target; the pixel cut decides where content breaks, and the compressor decides the weight.
