How it works


The square you drag is cropped from the original with Canvas before any scaling — only that area is used, so a tall screenshot no longer ends up centred inside an empty square.


An .ico file is a small container: a 6-byte header, one 16-byte directory entry per size, then the image data for each size. Modern readers accept PNG-compressed images inside that container, so each size is an ordinary PNG scaled with high-quality interpolation.


Everything is assembled with plain JavaScript in an ArrayBuffer. Nothing is sent to a server — the file is created in your browser and downloaded directly. Because each size is downscaled from the same source, details stay crisp at small sizes; artwork with tiny text will still lose legibility.

Frequently asked questions


Is this a real .ico file?
Yes. It contains a valid ICONDIR header, one directory entry per size, and PNG-compressed image data. Windows, macOS preview and browsers all open it.


Why are some sizes PNG data instead of BMP?
Since Windows Vista, .ico entries may hold a complete PNG. It is smaller and keeps an alpha channel, so transparency works without a separate mask.


Can I use a tall screenshot or a wide photo?
Yes. Drag the square selection over the part you want, move it or resize it from a corner, then generate. Only that 1:1 area becomes the icon — nothing is stretched. Press "Whole image" if you prefer the old fit-inside-a-square behaviour.


Does this upload my logo to a server?
No. The whole container is built in your browser with Canvas and plain JavaScript. The image never leaves your device.
Why is 16 × 16 blurry, and which size should I start from?
16 × 16 holds just 256 pixels. QR codes, faces and tiny text cannot survive it — that is a physical limit, not a scaling bug. Keep 16 px for legacy / Windows compatibility, start at 32 px for visible detail and use 64 px or larger for QR codes, portraits or screenshots with text. Draw the 16 / 32 px artwork separately with a bold, simple silhouette and high contrast.
