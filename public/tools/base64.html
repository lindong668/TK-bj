How it works

Base64 represents binary data using 64 printable characters (A–Z, a–z, 0–9, +, /). It splits every 3 bytes (24 bits) into four 6-bit groups, each mapping to one character.

Since 6 bits only express 0–63, matching exactly 64 characters, encoded data grows by about 33% (3 bytes become 4 characters). That is why Base64 images are larger than the original file.

On the web it is usually written as a Data URL: data:image/png;base64,xxxx. Browsers recognise this and load the text as an image resource, saving one HTTP request.

FAQ about Base64 conversion

Why is the result so much bigger?

Base64 encoding inherently adds about 33%, an unavoidable overhead of the scheme. Avoid inlining large images — it is meant for small icons of a few KB.

Can I paste Base64 without the data: prefix?

Yes. The tool adds the data:image/png;base64, prefix automatically before parsing. If the original is a JPG but the prefix says PNG, most browsers still identify it correctly.

Do line breaks or spaces matter?

Yes. Paste a continuous string. If the Base64 contains line breaks, remove them first.

Is there a size limit?

Image-to-Base64 is limited by browser memory, usually fine up to tens of MB. But an image over 1 MB becomes very large once encoded, so it is not recommended.
