How to resize an image

  1. Upload: Drop an image; its dimensions are shown as a reference.
  2. Choose how to resize: Scale by ratio, type the target width and height, or crop as needed. Tick "keep aspect ratio" to avoid distortion.
  3. Enter the target size: Enter width or height and the other follows the original ratio automatically, or set it by hand.
  4. Process and download: Check the result size before downloading.

Tip: All processing happens in your browser: images are never uploaded to a server. Results live only on this page, so download them promptly.

How it works

Resizing means resampling the pixel grid. When shrinking, many source pixels merge into one and the browser averages them so edges stay smooth. When enlarging, colours must be invented for positions that did not exist before, inferred only from neighbouring pixels.

That is why shrinking is almost always safe while enlarging blurs: shrinking discards excess information, enlarging has to fabricate it. However good the interpolation (bilinear, bicubic), it can only smooth the transitions — it cannot recover real detail.

The other key point is aspect ratio. Changing width without height stretches the image. Keeping the ratio means multiplying both by the same factor.

FAQ about resizing

Why is it blurry after enlarging?
Enlarging interpolates new pixels and cannot add real detail — that is a physical limit. Keep enlargements modest (under 1.5×), or find a higher-resolution source.
Why did my image distort when I changed the width?
Because the height was not changed to match. Tick "keep aspect ratio" so height follows automatically.
Does enlarging after shrinking restore quality?
No. Shrinking already discarded pixels; enlarging only interpolates them back, and quality does not return. Keep the original.
What if a platform requires under 2 MB?
Dimension limits and file size limits are different things. Shrinking dimensions reduces size; if that is not enough, use the Compress tool to tune quality.

Three modes, three different contracts

The mode selector is not cosmetic; each option computes the output size by a different rule, and mixing them up is the most common reason a resized image comes back distorted.

  • By ratio scales both dimensions by the same percentage, from 10% to 300%. The two results are rounded independently with Math.round, so an odd size can drift by one pixel.
  • Exact pixels takes width and height separately. With "keep aspect ratio" on and only one field filled, the other side is computed from the original proportion. With both fields filled, both values are used as typed — the aspect lock is satisfied, not enforced, so filling both is how you deliberately stretch.
  • Preset size sets an exact width and height from a fixed list: 1920×1080, 1280×720, 1080×1080, 1080×1350, 1200×630, 800×800 and 414×896.

That last one deserves a clear statement, because the page subtitle mentions cropping and the code does not crop. A preset sets the canvas to those dimensions and draws the whole image into it. A landscape photo sent to 1080×1350 is squeezed, not trimmed. To fill a portrait frame without distortion, resize with the aspect lock to the matching long edge, then cut the surplus with Crop Image.

Rounding drift, in real numbers

Rounding twice is harmless on large images and visible on small ones. Take a 999 × 1000 px file and scale it to 33%: the height becomes 330 and the width 330, so a 0.999 aspect ratio quietly becomes 1.000. Take 1001 × 1000 at 50%: 500 and 500, and the change is invisible. The drift only matters when you are matching a strict pixel box — an ID photo, a marketplace thumbnail, a favicon source — where the receiving system checks dimensions rather than appearance.

Scaling down also crosses a quality threshold. Halving is gentle, because the browser's smoothing has four source pixels for every destination pixel. Going from 1200 px to 120 px is a ten-to-one reduction, and thin lines, small type and one-pixel borders turn into grey mush. For anything below about 25% of the original, resize in two steps — 50%, then 50% again — and compare; the two-step version usually keeps stems and edges cleaner.

The 3000-pixel working ceiling

Before any resize happens, the editor fits the source onto a canvas whose longest side is at most 3000 px and reports the reduction underneath the original preview. Every mode then works from that canvas. Two consequences follow. First, "By ratio 100%" on a 6000 px photo returns a 3000 px file, not the original size. Second, upscaling to 300% produces 9000 px of interpolated pixels that contain no more detail than the 3000 px source — useful for meeting a minimum-size requirement, useless for recovering sharpness.

When the original really must be preserved at full resolution, do the resize outside the browser, or accept the cap and keep the untouched file as the master.

What resizing does not do

  • It does not change the file's byte size predictably. Output is always PNG, so a 1200 px JPEG often becomes a larger 1200 px PNG. Use Compress Image or Convert Format afterwards when the target is a byte budget rather than a pixel box.
  • It does not sharpen. Interpolation softens edges as it averages them. A light unsharp mask afterwards — the Colour Adjust page has one — restores local contrast without inventing detail.
  • It does not crop. See the preset note above.
  • It does not batch. One file per session.

Matching a platform's requirements

Platform specs are usually written as a pixel box plus a maximum file size, and the order matters. Resize first to the box, because interpolation changes the pixel count; compress second, because the encoder can then spend the byte budget on the final dimensions. Doing it the other way round means compressing pixels you are about to throw away, and often resizing after compression re-exposes artefacts that the smaller canvas would have hidden.

For social sharing cards the 1200×630 preset is exact and needs no crop on a 1.91:1 source; a square source will be stretched. For a store front image at 800×800 the same rule applies: crop to square first, then apply the preset, and the result is undistorted by construction.

Two more questions this page gets

Why is my 6000 px photo 3000 px after a 100% resize?
Because the editor fits the source onto a canvas capped at 3000 px on the long side before processing. The readout under the original preview states the reduction. Anything larger is outside the range the in-browser loop is tuned for.
I filled in both width and height and the picture stretched. Why?
With both fields populated the two typed values are used as given, so the aspect lock has nothing left to calculate. Leave one field empty to have it derived, or switch to By ratio for a proportional scale.
