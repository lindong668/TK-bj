How to use this tool

  1. Upload the image you want to mark up.
  2. Pick a tool: arrow and box are drawn by dragging; number and bubble are placed with a click.
  3. Set colour and stroke width; type the bubble text if you are using a bubble.
  4. Undo or clear as needed, then export the annotated PNG.

Note: All processing happens in your browser: images are never uploaded. Export the PNG before closing the page.

How it works

Each annotation is stored as a small object (type, coordinates, colour, line width, text) in an array. Rendering redraws the original image first, then replays that array onto the canvas, so undo and clear are instant and lossless.

Coordinates are converted from CSS pixels to canvas pixels using the bounding rectangle, so dragging stays accurate on a scaled mobile preview. The export is a flat PNG at the original resolution.

Frequently asked questions

Can I edit an annotation after placing it?
You can undo the last one or clear everything and start over. Individual editing is not in this version.
Does export reduce resolution?
No. The canvas keeps the original pixel dimensions, so the PNG is 1:1 with your source.
Why does my bubble text overflow?
Very long strings are drawn on one line. Keep bubble text short, or split it into several bubbles.
Are images uploaded?
No. Drawing and export are entirely local Canvas operations.

What the export actually contains

Every arrow, box, number and bubble is drawn onto a canvas built from the source image, then the whole canvas is flattened into one PNG. There is no layer file, no editable markup and no way to move an annotation after the file is saved. If a label is in the wrong place, the correct fix is to annotate again from the original image rather than to edit the exported PNG.

That also means annotations are pixels, not text. A bubble that says "Step 3" is not searchable, not selectable and not readable by a screen reader. If the note matters as text, put it in the surrounding document as well; the annotation is for the eye, not for the index.

Stroke width follows the preview, not the pixel grid

The stroke width control is measured in screen pixels. Before drawing, each value is multiplied by the ratio between the image's natural size and the preview's displayed size, so a 4 px setting looks 4 px while you work and stays proportionally the same in the exported file. This is why a stroke that looks right on a 4000-pixel photo can look heavy on a 600-pixel screenshot: the number is relative to the view, and the view is relative to the image.

A practical rule for screenshots and documents is to keep strokes between 0.25% and 0.5% of the image width. At 1200 px that is 3 to 6 px; at 4000 px it is 10 to 20 px. Below 0.2% the line all but disappears when the image is printed or viewed on a phone.

Inputs that are converted before you draw

The uploader accepts PNG, JPG, WebP, GIF, BMP, SVG, AVIF, ICO and HEIC/HEIF. Two of those behave differently from what the extension suggests:

  • SVG is rasterised at the size the browser renders it. Annotating a vector file therefore produces a bitmap; the output is not scalable.
  • GIF is decoded as a still image, so an animated file loses every frame but the first. There is no frame picker.

Everything else is decoded at its natural pixel dimensions, which is what the export preserves.

Colour, contrast and legibility

The colour control applies to strokes, box outlines and bubble fills. There is no automatic contrast adjustment, so a red arrow on a red subject disappears. Two habits prevent that: pick a colour that is absent from the area you are marking, and keep a light stroke dark or a dark stroke light. For screenshots of interfaces, a saturated accent such as #DB2777 or #2563EB reads clearly against both white and grey panels.

Undo, clear and starting over

Undo removes the most recent annotation; clear removes all of them. Loading a different file resets the canvas entirely. The counter under the preview reports the current image dimensions and how many annotations are on it, which is the quickest way to confirm that a stray click did not add an invisible box somewhere outside the visible area.

What this tool does not do

  • No redaction guarantee. A filled box hides content visually, but the underlying pixels are still in the exported file if the box is semi-transparent. Use the Mosaic tool for anything that must be unrecoverable.
  • No callout leaders or freehand drawing. The tools are arrows, rectangles, numbered markers and text bubbles.
  • No layer editing after export. See above: the PNG is final.
  • No batch mode. One image per session.

Annotations on a screenshot: a short checklist

  1. Load the image at 100% zoom before placing the first mark, so stroke widths are judged against real pixels.
  2. Place the mark, then check the counter: the annotation count should match what you intended.
  3. Keep numbers sequential and consistent in meaning across the whole document.
  4. Export as PNG. JPEG would add compression artefacts around thin strokes and text.
